研究方法论与工具说明

主题：方法 / 工具 / 工作流
范畴：数字人文、文献学、比较哲学、知识管理
关键词：文本优先、五重视角、可验证、可迭代、Markdown、Python、Git

1. 为何需要一份方法论说明

《易经》是中国古代最难读的经典之一。其困难不仅在于文字古奥、版本纷繁，更在于它同时承担着卜筮手册、哲学文本、历史档案与象征符号系统四种角色。若不先确立阅读与研究的“操作协议”，很容易在经、传、注、术四个层次之间滑移，或将某一时代的解释错置为《易经》本身的原意。

本项目的方法论说明，旨在为所有后续报告提供统一的研究规范：

  1. 读什么：明确文本边界与优先使用的版本。
  2. 怎么看：确立“文本—象数—义理—历史—比较”五重视角。
  3. 怎么写：统一报告结构、注释方式与可迭代格式。
  4. 怎么管：以 Markdown、Git、脚本实现可复现、可扩展的知识生产。

2. 研究原则

2.1 文本优先

一切阐释必须回到原文、原注与原语境。这意味着：

  • 讨论卦辞时，优先引用通行本《周易》原文，并说明所用版本。
  • 讨论《易传》时，区分《彖》《象》《文言》《系辞》《说卦》《序卦》《杂卦》的成书背景。
  • 讨论象数时，明确所据是汉代象数、王弼玄学义理，还是宋明理学图式。
  • 讨论占卜应用时，区分经文本义与后世术数推演。

2.2 方法多元

《易经》本身就是一个跨学科文本。本项目的研究兼容：

  • 文献学：版本对照、文字训诂、篇章结构分析。
  • 哲学分析：概念澄清、论证重构、范畴谱系。
  • 统计学与文本计量：词频、共现网络、主题模型。
  • 概念史：核心术语在不同历史时期的语义变迁。
  • 比较研究：跨文明、跨经典的哲学对话。

2.3 可验证

重要结论须注明出处、版本与推理链条。具体做法包括：

  • 引文注明书名、篇名、版本与页码（或电子文本链接）。
  • 统计结论说明数据来源、处理步骤与可复现脚本。
  • 比较研究避免“攀附式类比”，须先说明比较基点的合理性。

2.4 可迭代

每份报告不是最终答案，而是后续研究的模块。为此：

  • 使用 Markdown 作为源文件，便于版本控制与增量修订。
  • 每份报告末尾列出“发现与待延伸问题”，指明下一步方向。
  • 使用双链标记（如 [[reread-yijing-framework]]）建立报告之间的关联。

3. 五重视角分析框架

本项目强调从五个视角切入《易经》，彼此补充，而非互相取代。

3.1 文本层

关注《易经》作为文本的物质形态与层累结构：

层级 内容 关键问题
经 六十四卦卦符、卦名、卦辞、爻辞 文本来源、层累形成、巫史传统
传 《十翼》 战国至汉代的哲学化阐释
注疏 王弼、韩康伯、孔颖达、朱熹、来知德等 各时代如何重释易理
术数 揲蓍法、纳甲、梅花易数、奇门遁甲 象数系统与占卜实践

3.2 象数层

关注《易经》的符号系统与推演规则：

  • 阴阳：从爻画到二元范畴的哲学化。
  • 八卦：乾、坤、震、巽、坎、离、艮、兑的象征体系。
  • 六十四卦：卦序、卦变、错综、往来。
  • 爻位：当位、相应、乘承、往来、进退、得失。
  • 大衍之数：揲蓍法的数学结构与概率分布。

3.3 义理层

关注《易经》的哲学概念与价值体系：

天 ─ 道 ─ 命 ─ 性 ─ 情 ─ 欲
│
├─ 易：变易、不易、简易
├─ 生生：天地之大德曰生
├─ 时中：与时偕行、得中得正
├─ 忧患：亢龙有悔、惧以终始
├─ 感通：寂然不动，感而遂通
└─ 象意：立象以尽意，得意而忘象

3.4 历史层

关注《易经》在不同时代的生成与解释变迁：

  1. 巫易时代（商周）：卜筮原始形态。
  2. 史易时代（西周至春秋）：卦爻辞编纂，史官文化。
  3. 哲易时代（战国）：诸子借易立说，《易传》形成。
  4. 玄易时代（汉魏）：象数易学、王弼玄学义理。
  5. 理易时代（宋明）：程朱理学、陆王心学与易学。
  6. 现代易学：考古新材料、海外汉学、数字人文。

3.5 比较层

关注《易经》与其他思想传统的对话：

  • 与道家：老庄的“道”与《易》之“道”。
  • 与儒家：孔子“五十以学易”、孟子“尽心知性知天”。
  • 与佛学：华严“理事无碍”与易之象数结构。
  • 与西方哲学：赫拉克利特“流变”、怀特海“过程哲学”、莱布尼茨二进制。
  • 与现代科学：系统论、复杂性科学、量子互补与阴阳模型。

4. 报告写作模板

为保证系列报告风格一致、便于检索，每份报告建议采用以下结构：

# 报告标题

## 1. 问题缘起
- 研究动因与核心问题

## 2. 文献基础
- 核心文本、版本、注疏

## 3. 分析框架
- 采用的本报告视角（文本/象数/义理/历史/比较）

## 4. 主体论证
- 分层推进、引证并行

## 5. 发现与结论
- 主要观点、限制与可延伸之处

## 6. 附录
- 卦图、表格、代码、延伸阅读

单卦报告可在此基础上有一定灵活性，但应包含以下要素：

  • 卦象与卦名训诂
  • 卦辞、爻辞逐句疏解
  • 彖传、象传、文言阐释
  • 核心义理提炼
  • 历史案例或现实映照
  • 与相关卦的比较（错、综、复、杂）

5. 数字工具与工作流

5.1 文本与知识管理

  • Markdown：所有研究报告的源文件格式，便于版本控制与跨平台编辑。
  • Git：版本控制，记录每次修改的作者、时间与理由。
  • GitHub Pages：静态站点托管，使报告可被公开访问。
  • Obsidian / 任何 Markdown 编辑器：本地知识管理与双链阅读。

5.2 文本处理与数据分析

  • Python：主力脚本语言。
  • pandas：结构化数据处理。
  • jieba：中文分词。
  • networkx：概念共现网络与卦变网络分析。
  • matplotlib / seaborn：统计可视化。
  • 正则表达式与文本解析：用于提取卦辞、爻辞、注疏文本。
  • CSV / JSON / YAML：结构化存储卦名、爻位、错综关系等数据。

5.3 可视化

  • ECharts / D3.js：交互式卦序图、卦变网络、概念共现图。
  • matplotlib / TikZ：静态图表与概念图。
  • Mermaid / Graphviz：流程图与结构图。

5.4 自动化脚本

项目提供 scripts/md_to_html.py，可将 docs/ 下的 Markdown 文件批量转换为 GitHub Pages 可用的 HTML。

pip install -r requirements.txt
python scripts/md_to_html.py

转换规则：

  • docs/hexagrams/01-qian.md → hexagrams/01-qian.html
  • docs/themes/foo.md → themes/foo.html
  • 相对 .md 链接自动重写为 .html
  • index.html 为自定义首页，需手动维护

7. 质量控制与研究守则

7.1 质量控制

  1. 初稿：按模板完成主体内容。
  2. 自审：检查引文、逻辑链条、术语一致性。
  3. 交叉审读：与相关报告对照，避免矛盾或重复。
  4. 修订：根据新材料与新思考持续更新。

7.2 研究守则

  1. 不将《易经》简化为占卜手册，也不神化其为万能体系。
  2. 区分“经”“传”“注”“术”四个层次，避免时代错置。
  3. 对考古新材料保持敏感，对过度推测保持警惕。
  4. 在跨文明比较中，先做“同情的理解”，再做“批判的辨析”。

8. 发现与待延伸问题

8.1 本报告核心发现

  1. 本项目采用“文本—象数—义理—历史—比较”五重视角，避免单一视角的还原主义。
  2. Markdown + Git + Python 构成可复现、可迭代的研究基础设施。
  3. 统一模板与引用规范是系列报告保持一致性的关键。

8.2 可延伸研究

  • 建立项目专用的卦爻辞结构化数据库（CSV/JSON）。
  • 开发卦变网络与概念共现的自动化可视化脚本。
  • 对比通行本、帛书本、竹简本的差异并生成版本对照表。
  • 探索大衍揲蓍法的概率模拟与统计验证。
